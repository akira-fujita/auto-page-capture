# 章扉検出・テキスト検出（設計）

作成日: 2026-08-06

## 背景

既存の目次解析（`PdfTocAnalyzeDialog` + `ClaudeTocEngine`）は、
**目次にページ番号が印字されている**ことを前提にしている。
目次から `(章名, 印字ページ)` を読み、アンカー1点でオフセットを補正して物理ページを出す。

しかし Kindle を画面キャプチャした PDF（このアプリ自身の出力を含む）では:

1. **テキスト層が1文字も無い**（全ページ画像）
2. **目次にページ番号が印字されていない**（Kindle の目次はリンクのみ）

実物 `イシューからはじめよ.pdf`（211ページ）で確認したところ、両方に該当した。
この場合、目次解析はどう頑張っても物理ページを出せない。

## 追加する2経路

| 経路 | 使う場面 | claude 呼び出し | 得られるページ |
|---|---|---|---|
| **テキストから検出** | しおり付き、または本文がテキストのPDF | なし（無料） | 物理ページ（しおり・本文見出し）／印字ページ（目次のみの場合） |
| **章扉から検出** | 目次にページ番号が無い本、スキャンPDF | あり（利用枠を消費） | 物理ページ（実測） |

既存の目次解析は変更しない。3つはボタンで並列に選べ、結果はすべて
`PdfTocAnalyzeDialog` の同じ表（章名 / ページ範囲 / 出力チェック）に入る。
選別（章のみ・全選択・全解除）と「この内容で章を設定」は共通のまま使える。

## テキストから検出

`PdfSplitter.detect_chapters_auto()`（新規）:

1. **しおり**（`reader.outline`、トップレベルのみ・空タイトルは除外）
2. 無ければ `extract_page_texts()` → `toc_detector.detect_chapters_from_text()`
   - 目次ページを特定して本文走査から除外
   - 本文の `第N章` / `第一章` / `Chapter N` 見出しの**初出ページ**を実測
   - 見出しが取れず目次だけある場合は目次の印字ページを返す（`source="toc"`）
3. テキストが実質空なら `has_text_layer=False` を返し、章扉検出を案内する

不変条件（範囲内・厳密増加・重複なし）と、外れ値に強い最長整合列（LIS）による
選別は `toc_detector` 側で担保する。

## 章扉から検出（2パス）

`src/export/page_sheet.py` + `src/export/chapter_cover_detector.py`

1. **1パス目**: 全ページを 36ページ/枚（6列×6行、240×320px）のコンタクトシートにして
   1枚ずつ claude に渡し、章扉ページの物理ページ番号を得る
2. **2パス目**: 1パス目のページだけを拡大（2列・600×800px）して渡し、
   - そのページが**本当に章扉か**を検証（`is_chapter_start` が `true` のときだけ採用）
   - **印字されている章名を書き写させる**（推測禁止）

1パス目だけではサムネイルが小さく、章番号を読み違える（実測で「第2章」を「第3章」と
誤答し、ページも 144→136 とズレる実行があった）。2パス目が検証と正名の役割を持つ。

claude CLI の呼び出しは既存 `ClaudeTocEngine` の流儀に合わせる:
**画像のあるディレクトリを cwd にし、プロンプトではベース名で参照**する
（ヘッドレスの claude は cwd 配下しか追加許可なしに Read できない）。
`--output-format json` の `result` を取り出してから JSON を解析する。

### 検証結果（実物 PDF・211ページ）

```
p.  15  0 序章 この本の考え方——脱「犬の道」
p.  35  1 イシュードリブン 「解く」前に「見極める」
p.  79  2 仮説ドリブン① イシューを分解し、ストーリーラインを組み立てる
p. 106  3 仮説ドリブン② ストーリーを絵コンテにする
p. 144  4 アウトプットドリブン 実際の分析を進める
p. 162  5 メッセージドリブン 「伝えるもの」をまとめる
```

手作業で全ページを目視して確認した正解と完全一致（3回実行して同一）。

## UI と安全性

- **実行前に確認**: 章扉検出はページ画像が外部（Claude）に渡り利用枠も消費するため、
  ページ数と所要時間の目安を示して都度確認する
- **UI を止めない**: `_CoverDetectWorker`（`QThread`）で実行し、進捗表示とキャンセルを提供
- **アンカーで壊れない**: 章扉・テキスト検出は物理ページ直取りなので、
  アンカーや目次ページ範囲を動かしても結果を再計算しない（`_mode` で区別）
- **サマリに検出元を出す**: 「章扉から N 件検出」「しおりから N 件検出」など
- **検証**: ページは 1-indexed・文書範囲内・厳密増加・重複なしを UI 側でも強制する
  （`QSpinBox` の暗黙の丸めに頼らない）。章名が空なら `章扉 p.N` にフォールバック

## 既知の限界

- `claude` CLI のインストールとログインが前提
- 章扉が視覚的に本文と区別できない本では検出できない
- 1パス目の結果は実行ごとに揺れる。2パス目の検証で誤りは落ちるが、
  取りこぼし（本物の章扉を見逃す）は起こり得るため、表示されたページの確認は必須
